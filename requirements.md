# Lost-and-Found Mobile App — Requirements

## 1. Functional Requirements

Functional requirements describe what the Lost-and-Found mobile application should be able to do.

| ID | Functional Requirement |
|---|---|
| FR1 | The system shall allow users to register and log in. |
| FR2 | The system shall allow users to report a lost item. |
| FR3 | The system shall allow users to report a found item. |
| FR4 | The system shall allow users to enter item details such as name, category, description, location, and date. |
| FR5 | The system shall allow users to upload an image of a lost or found item. |
| FR6 | The system shall allow users to search for lost and found items. |
| FR7 | The system shall allow users to filter items by category, location, and date. |
| FR8 | The system shall display details of reported items. |
| FR9 | The system shall allow users to submit a claim for a found item. |
| FR10 | The system shall allow users to track the status of submitted claims. |
| FR11 | The system shall provide confirmation after a lost/found report or claim is submitted. |
| FR12 | The system shall allow administrators to review reported items and claims. |
| FR13 | The system shall allow administrators to approve or reject claims. |
| FR14 | The system shall allow users to view the status of their reported items. |
| FR15 | The system shall notify users when there is an update to their report or claim. |

## 2. Usability Requirements

These requirements focus on making the mobile application easy, efficient, understandable, and safe to use.

| ID | Usability Requirement |
|---|---|
| UR1 | The app shall have a simple and easy-to-understand interface. |
| UR2 | Users shall be able to report a lost or found item within a few simple steps. |
| UR3 | Navigation elements shall be consistent across all screens. |
| UR4 | Buttons and interactive elements shall be large enough for comfortable touch interaction. |
| UR5 | Important actions such as **Report Lost**, **Report Found**, **Search**, and **Claim** shall be clearly visible. |
| UR6 | Forms shall use clear labels and appropriate input fields. |
| UR7 | The system shall provide immediate feedback when an action is successfully completed. |
| UR8 | The system shall display clear error messages when users enter invalid or incomplete information. |
| UR9 | The system shall prevent users from accidentally submitting incomplete reports or claims. |
| UR10 | Search and filtering shall provide relevant results without unnecessary complexity. |
| UR11 | The app shall use readable text, appropriate spacing, and clear visual hierarchy. |
| UR12 | Users shall always be able to understand the current status of their report or claim. |
| UR13 | The app shall minimize the amount of information users need to enter manually. |
| UR14 | The app shall use familiar mobile interaction patterns such as tapping, scrolling, selecting, and uploading images. |
| UR15 | The app shall protect sensitive user information and avoid unnecessarily displaying personal details. |
